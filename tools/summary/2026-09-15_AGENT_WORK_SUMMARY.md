# Тестовая оплата подписки через ЮKassa

## Уточнение тарифов после первой сборки

- Пользователь запросил явную цепочку: первая кнопка «Купить» → выбор месяца
  или года → «Оплатить» → ЮKassa после добавления ключей.
- Месяц оставлен 100 ₽ / 30 дней, год согласован 990 ₽ / 365 дней.
  Экономия относительно 12 месяцев — 210 ₽, скидка 17,5%.
- `/menu` возвращает главное меню; в карточках есть отдельные кнопки выбора
  тарифа и главного меню. Без ключей доступны оба тарифа и карточки.
- Добавлены planId и metadata.plan_id для новых заказов; старые месячные заказы
  без этих полей остаются совместимыми и сохраняют исходный payload.
- Это уточнение сделано после коммита и сборки 0.1.39, описанных ниже.
- Для уточнения подготовлена версия 0.1.40: все 167 тестов прошли,
  `docker compose build` собрал `benz-ai:local`. Проверка контейнера подтвердила
  HTTP health, первую кнопку «Купить», тарифы и скидку, non-root запуск и запись
  заказов в выделенный том. Реквизиты магазина по-прежнему ожидаются.

## Продуктовая цель

- Пользователь готовит регистрацию ЮKassa и хочет готовый платёжный сценарий
  существующего Telegram-бота. В качестве UI-образца дал магазин с кнопками
  «Купить» и «Оплатить»; тексты и товары образца переносить не требовалось.
- Единственный товар — подписка на рассылку и поиск дешёвого бензина с
  вероятным наличием рядом. Подтверждены цена 100 ₽ и срок 30 дней.
- Цель итерации — тестирование оплаты. Рассылка, поиск по геопозиции, paywall,
  автопродление и реальные продажи в эту итерацию не входят.

## Реализованный сценарий

- `/start` показывает меню, `/buy` — карточку, «Оплатить» создаёт тестовый
  платёж и выдаёт ссылку ЮKassa. Кнопка проверки и `/subscription` подтверждают
  последний заказ через API. До получения реквизитов карточка доступна,
  а оплата сообщает, что подключение магазина ожидается.
- Заказы сохраняются атомарно в частном `data/payments/orders.json`.
  Docker использует постоянный volume `payments`. Один файл обслуживает один
  polling-процесс. Секретов в файле нет; Telegram ID владельца является частным.
- Повторы и перезапуск сохраняют ключ идемпотентности и исходный запрос.
  Неопределённый результат старше 23 часов требует проверки в кабинете ЮKassa.
- Перед активацией сверяются владелец, магазин, metadata, сумма, валюта,
  `test=true`, `succeeded` и `paid=true`. Повторы не продлевают подписку.
- Контракт: `tools/project-memory/specs/subscription-payments.md`.
  Подключение и ручной сквозной тест: `docs/yookassa-testing.md`.

## Оставшиеся границы

- Пользователь ещё регистрирует магазин; реквизитов ЮKassa в локальном `.env`
  нет. Сквозной тест реального тестового магазина ещё не выполнен.
- Публикация на действующий сервер не выполнялась. Сборка и отправка исходников
  в Git сами по себе не подтверждают обновление работающего бота.
- Для цифровой подписки внутри Telegram правила требуют Stars при реальной
  продаже. Текущий модуль намеренно принимает только тестовые ключи и платежи.
