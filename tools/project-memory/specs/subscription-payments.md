# Тестовая подписка: контракт платежей

## Цель и границы

Запрос пользователя от 2026-09-15: проверить связку существующего Telegram-бота
и ЮKassa на одном товаре, с шагами «Купить → Оплатить». Товар — подписка на
рассылку и поиск дешёвого бензина рядом. Позже согласованы два тарифа:
месяц (30 дней) — 100 ₽; год (365 дней) — 990 ₽, экономия 210 ₽ / 17,5%.
Регистрация магазина продолжается; реальные реквизиты пока не предоставлены.
Подключение модуля не означает прохождение сквозного теста внешнего магазина.

Рассылка, геопозиционный поиск, paywall, автопродления и реальные продажи
не входят в эту итерацию. Тестовая подписка хранит результат проверки оплаты.
Существующий поиск по территории остаётся доступен независимо от покупки.

## Ответственность модулей

- `services/subscription-config.js`: параметры магазина, товар, цена и срок;
  режим включается явно, допускается только тестовый ключ, HTTPS return URL.
- `providers/yookassa.js`: Basic Auth, POST `/v3/payments`, GET статуса,
  timeout, запрет redirects, безопасные ошибки без сырого ответа и секретов.
- `services/payment-store.js`: JSON версии 1, очередь операций, атомарная
  замена файла; один процесс. Повреждение файла не считается пустой базой.
- `services/subscription-payments.js`: владение заказом, неизменяемый запрос,
  идемпотентность, сверка ответа и подтверждение тестовой подписки.
- `services/subscription-menu.js`: тексты товара и inline-клавиатуры.
- `services/telegram-gateway.js`: callback_query, ранний answerCallbackQuery,
  нормализация пользователя нажавшего кнопку, структурированный sendMessage.
  Просроченный acknowledgement не мешает обработке сохранённого заказа.
- `server.js`: сборка зависимостей, безопасный health-статус.

## Состояния и инварианты

1. `/start` и `/menu` показывают первую кнопку «Купить». `/buy` и `sub:buy`
   показывают два тарифа. `sub:plan:month|year` открывает карточку и получает
   незавершённый заказ владельца выбранного тарифа либо создаёт draft.
   До ключей карточки обоих тарифов доступны без создания заказов.
   Назад ведёт к выбору тарифа; отдельная кнопка — в главное меню.
   Цена года задаётся SUBSCRIPTION_YEAR_PRICE_RUB, срок — 365 дней.
   Скидка вычисляется относительно 12 месячных цен, положительное значение
   показывается с точностью до десятых процента. При отсутствии экономии скрыта.
   Старые заказы без planId считаются месячными; их payload не меняется.
2. До включения магазина показывается полноценная карточка; «Оплатить»
   возвращает сообщение о недоступности. Внешних вызовов и draft-записей нет.
3. Только личный чат с совпадающими userId и chatId может работать с заказом.
   Чужой UUID и callback из группы не дают доступ к заказу.
4. До первого запроса сохраняются UUID заказа (он же Idempotence-Key), сумма,
   валюта, срок, return URL, metadata и attemptedAt. Секреты не сохраняются.
5. Повторное создание после неизвестного результата использует тот же payload
   и ключ; после 23 часов блокируется до проверки администратором. Параллельные
   запросы одного заказа внутри процесса объединяются.
6. При известном paymentId используется GET. `pending` выдаёт только проверенный
   HTTPS URL доменов ЮKassa/ЮMoney. `waiting_for_capture` не активирует подписку.
7. Перед сохранением ответа совпадают ID платежа, metadata заказа/товара/тарифа,
   сумма/валюта, recipient.account_id и test=true.
8. `succeeded` требует paid=true и корректного captured_at. expiresAt равен
   captured_at + срок заказа. Повторная проверка не продлевает срок.
9. `canceled` ничего не активирует и разрешает новый draft. Неподходящий ответ
   ничего не активирует. Терминальные результаты хранятся локально без повторной
   синхронизации возвратов. `/subscription` работает с последним заказом;
   просмотр нетронутого draft не создаёт платёж.
10. Карточка явно описывает тестовый режим и отсутствие рассылки/поиска по
    геопозиции. Возврат из браузера не считается платёжным подтверждением.

## Хранилище и проверка

Частные заказы — `data/payments/orders.json`, Docker volume `payments`.
Не смешивать их с PostgreSQL аналитики или памятью агента. Не удалять неизвестные
платежи, не запускать несколько владельцев файла. Максимум 10 000 заказов.
Новые публичные HTTP payment-endpoints отсутствуют; достаточно кнопки проверки.
Проверки инвариантов: `subscription-payments.test.js` и `telegram.test.js`.
Инструкция подключения и оставшийся сквозной тест: `docs/yookassa-testing.md`.
