# Тестовая подписка и ЮKassa

## Готовый сценарий

1. В личном чате открыть `/start` и нажать «Купить».
2. Выбрать срок: месяц (30 дней) за 100 ₽ или год (365 дней) за 990 ₽.
   Год дешевле 12 месячных подписок на 210 ₽ (17,5%). После выбора появляется
   карточка тарифа с кнопкой «Оплатить». `/menu` возвращает первую кнопку «Купить».
3. «Оплатить» создаёт тестовый платёж и показывает ссылку на страницу ЮKassa.
4. Завершить оплату на стороне ЮKassa, вернуться в бот и нажать
   «Проверить оплату» или отправить `/subscription`.
5. Бот получает платёж через API, сверяет магазин, заказ, товар, сумму, валюту,
   тестовый режим и статус. Только `succeeded` с `paid=true` активирует запись
   тестовой подписки. При отмене появляется возможность нового заказа.

Подписка здесь — тестовая запись, а не платный доступ к работающей рассылке.
Рассылка и поиск по геопозиции ещё не подключены. Обычный поиск по названию
территории работает независимо от оплаты. Автопродления и сохранения карты нет.

## Настройки после регистрации магазина

Модуль уже включён в сервер и бот. До получения реквизитов доступны меню,
карточка и кнопка оплаты; нажатие объясняет, что магазин ещё не подключён.
Без реквизитов ЮKassa нельзя сформировать настоящую тестовую платёжную ссылку.

В игнорируемом `.env` заполнить:

```dotenv
TELEGRAM_POLLING_ENABLED=true
TELEGRAM_BOT_TOKEN=<токен существующего бота>
YOOKASSA_TEST_ENABLED=true
YOOKASSA_SHOP_ID=<идентификатор тестового магазина>
YOOKASSA_SECRET_KEY=<секретный ключ тестового магазина с префиксом test_>
YOOKASSA_RETURN_URL=https://t.me/<имя_бота>?start=payment_return
YOOKASSA_DATA_FILE=data/payments/orders.json
SUBSCRIPTION_PRICE_RUB=100.00
SUBSCRIPTION_YEAR_PRICE_RUB=990.00
SUBSCRIPTION_DAYS=30
```

Секреты не размещать в Git, чатах или документации. После изменения настроек
перезапустить единственный процесс `npm start` либо контейнер приложения.
Не запускать одновременно два polling-процесса с одним токеном.
`GET /api/health` содержит `payments.enabled` и `payments.testOnly` без реквизитов.

По документации [ЮKassa о тестовом режиме](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing),
тестовый магазин позволяет проверять оплату без движения реальных денег.
Для успешного теста можно использовать номер `5555 5555 5555 4444`, будущую дату
и любой CVC. Вводить карту следует только на странице ЮKassa.

## Хранение и повторы

- Заказы хранятся в `data/payments/orders.json` (Git игнорирует каталог).
  В нём есть Telegram ID владельца, сумма, статус и идентификатор платежа;
  ограничьте доступ к файлу и сохраняйте его при перезапусках.
- В Docker используется отдельный постоянный volume `payments`, доступный
  пользователю `node`. Остальная файловая система контейнера остаётся read-only.
- Файлом владеет один экземпляр приложения. Несколько экземпляров потребуют
  отдельного транзакционного хранилища; текущий тестовый модуль для них не подходит.
- Запрос и ключ идемпотентности записываются до HTTP-вызова. При сетевой ошибке
  повторяется тот же заказ с той же суммой и ключом, включая после перезапуска.
- Если результат создания неизвестен дольше 23 часов, новый запрос по этому
  заказу блокируется: администратор должен проверить его в кабинете ЮKassa.
  Нельзя удалять запись ради повторной оплаты с неизвестным результатом.
- Повторная проверка не продлевает подписку: срок считается от `captured_at`.
  Месячный и годовой заказы независимы; смена тарифа не меняет сумму старого
  заказа. Старые заказы без planId остаются месячными. Скидка рассчитывается
  из текущих цен и скрывается, если год не дешевле 12 месяцев.
  Повторная покупка создаёт отдельную тестовую подписку, сроки не суммируются.
- `/subscription` показывает последний заказ. Статус проверяется по запросу
  пользователя; публичный webhook и фоновая рассылка не нужны для этого теста.
- Возврат из браузера сам по себе не подтверждает оплату. Уже подтверждённые
  заказы показываются из локального хранилища; возвраты средств и отзыв подписки
  не входят в тестовый модуль.
- Предел хранилища — 10 000 тестовых заказов; автоматического удаления нет.

## Проверка

```powershell
node --test subscription-payments.test.js telegram.test.js
npm test
```

Автотесты заменяют API ЮKassa и Telegram контролируемыми ответами, не создают
внешних платежей и не отправляют сообщения. Они проверяют полный путь покупки,
сбой сети, повторы, перезапуск, отмену, права владельца и неподходящие платежи.
Сквозной тест с настоящим тестовым магазином нужно провести после выдачи реквизитов.

## Граница тестового режима

Код отклоняет live-ключи и ответы без `test=true`. Для этой цифровой подписки
внутри Telegram перед запуском реальных продаж следует использовать
[Telegram Stars](https://core.telegram.org/bots/payments-stars).
Настоящий приём денег, фискализация и правила оказания платной услуги здесь
не включены. Не меняйте описание товара на физический товар ради обхода правил.
