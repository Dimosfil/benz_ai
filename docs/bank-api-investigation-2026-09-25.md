# Банковские API: проверка 25 сентября 2026

## Результат

Цены для двух проблемных станций действительно доступны в API Альфа-Банка.
Текущий URL и формат ответа поддерживаются существующим `providers/alfa.js`.
Главная воспроизведённая причина недоступности Альфы и T-Bank — отсутствие
доверия к Russian Trusted Root CA, а не смена адреса API или необходимость
авторизации банковским аккаунтом.

Исследование выполнено из локального Node.js 24.14.1; также прочитан публичный
`/api/health` Benz AI версии 0.1.46 на BotHost. Прямой банковский запрос из
контейнера BotHost не выполнялся: его транспортная причина пока не подтверждена
отдельным логом TLS. В Dockerfile установлен стандартный `ca-certificates`,
дополнительный российский CA для Node не настроен.

## T-Bank и Альфа: воспроизведённая причина и проверка решения

Обычный Node `fetch` к обоим источникам завершился `fetch failed`,
`cause.code = SELF_SIGNED_CERT_IN_CHAIN`. PowerShell сообщил `UntrustedRoot`.

Официальные инструкции:

- [Т-Банк: сертификаты и доступ к API](https://status.tbank-online.com/certificates/).
- [Альфа-Банк: переход на российские сертификаты](https://alfabank.ru/cert/).
- [Node.js: NODE_EXTRA_CA_CERTS](https://nodejs.org/api/cli.html#node_extra_ca_certsfile).

Для контрольного запроса сертификат получен по HTTPS с адреса, указанного
в инструкции Т-Банка:
`https://help-static2.tbank-online.com/certs/Wind_russian_trusted_root_ca.cer`.

- Subject/issuer: Russian Trusted Root CA, The Ministry of Digital Development and Communications.
- SHA-256 сертификата: `D26D2D0231B7C39F92CC738512BA54103519E4405D68B5BD703E9788CA8ECF31`.
- Действителен до 27 февраля 2032, 21:04:15 GMT.
- Временный HTTPS-клиент добавил этот CA к штатным CA только для двух банковских
  хостов. Проверка цепочки и имени хоста оставалась включённой;
  `rejectUnauthorized=true`, `socket.authorized=true`.
- Системное хранилище, конфигурация приложения и окружение BotHost не изменялись.
- T-Bank ответил HTTP 200. Альфа: HTTP 307, затем HTTP 200 с cookies,
  обработанными существующим `requestAlfaRows`. Cookies не сохранены.

## Точные контракты и примеры

### Альфа — подтверждённый источник цен

`GET https://alfabank.ru/api/v1/azs-stations/public/stations?g=%5B39.3769,51.6927%5D&z=14`

Получен массив 16 479 станций. Сервер по-прежнему возвращает общий снимок;
нужны существующие кэширование и фильтрация территории. Цена находится в
`fuels[].price`, вид топлива — в `fuels[].category`, время операции —
в `fuels[].last_transaction_at`. Отдельная дата публикации цены не установлена.

| Станция | AI92 | AI95 | AI98_100 | DIESEL |
| --- | ---: | ---: | ---: | ---: |
| Газпром, АЗС №298, Бабяково | 65.25 | 71.75 | 97.20 | 77.10 |
| Лукойл, Цветочная, 26 | 67.02 | 72.89 | 99.40 | 80.52 |

Это значения из проверенного ответа, не константы приложения и не гарантия
цены на колонке. Категорию `AI98_100` нельзя произвольно переименовывать в АИ-100.
Статусы топлива могут расходиться с другими банками; цена не доказывает наличие.

ID Газпрома: `e5423f40-15e0-42ea-b67d-bc619f347fef`, координаты
`51.69268,39.37693`. ID Лукойла: `c36c3ac4-8d98-4d92-98c4-d710f873bd79`,
координаты `51.676441,39.333265`.

### T-Bank — оплаты и идентификаторы; поле цен в проверенной выборке пустое

`GET https://toplivo.tbank.ru/api/v1/stations?minLat=51.67&maxLat=51.70&minLon=39.32&maxLon=39.39`

Получены `status=ok`, `payload` из четырёх станций. Поля прежнего адаптера
сохранились. В ответе присутствует `priceByFuelType`; у проверенных Газпрома
и Лукойла оно пустое. Текущий `normalizeTbankStation` это поле не читает. Формат непустого
значения пока не подтверждён; придумывать его или объявлять все цены T-Bank
доступными нельзя.

- Газпром: `yandexOrgId=38745431337`, `lastTransactionAt=2026-09-25T11:57:37.554Z`
  (14:57:37 по Москве), `status=available`.
- Лукойл: `yandexOrgId=1163758777`, `lastTransactionAt=2026-09-25T11:57:51.079Z`
  (14:57:51 по Москве), `status=available`.

### Сбер — прямой JSON работает, цены в проверенном ответе отсутствуют

`GET https://sberazs.ru/api/stations?bbox=39.32,51.67,39.39,51.70`

Обычный Node `fetch` без cookies и без Chromium вернул HTTP 200, `apiVersion=1`,
шесть станций, `lastErrorPresent=false`. Поля `stations`, `lastPaymentAt`,
`fuels`, `location` совместимы с текущим нормализатором. Поля цен не найдены.

- Лукойл, Цветочная, 26: `lastPaymentAt=2026-09-25T14:59:10+03:00`,
  `operationsCount=6`, `availabilityStatus=available`.
- У записей Газпрома/Газпромнефти около `51.692568,39.377002` поле
  `lastPaymentAt` отсутствует. Поэтому отметку оплаты для этой АЗС даёт T-Bank,
  а не проверенный ответ Сбера.
- Публичный health Benz AI: `lastStopReason=start_failed`,
  `lastError=Sber AZS не завершил браузерную JavaScript-проверку`.
- Наш `SberBrowserWorker.start()` обязательно ждёт cookie `__jhash_` и текст
  `КАРТА ЗАПРАВОК`. Нынешняя страница и JS-бандл `/assets/index-D365T-ae.js`
  эту строку не содержат. Доступный JSON не должен зависеть от этих маркеров.

## Предлагаемые изменения и критерии приёмки

1. Настроить доверенный CA для процесса приложения в контейнере, например через
   проверенный PEM и `NODE_EXTRA_CA_CERTS`, заданный до старта Node; либо
   ограничить дополнительный CA банковскими HTTPS-клиентами. Сохранить TLS-проверку.
2. Для Сбера сначала запрашивать JSON напрямую. Обращение к браузеру использовать
   только при фактическом HTML-челлендже; готовность проверять по ответу API,
   а не по устаревшей cookie и заголовку страницы.
3. Сохранить текущую нормализацию цен Альфы и проверить объединение конкретных
   станций. Поддержку `priceByFuelType` T-Bank добавлять после получения примера
   непустого значения или подтверждённой схемы.
4. Показывать в диагностике причину TLS/таймаута/неизвестного формата отдельно,
   чтобы `fetch failed` не маскировал источник проблемы.
5. После пересборки проверить именно BotHost: источники Альфа и T-Bank доступны,
   Газпром и Лукойл получают банковские цены/оплаты, нет ложной подстановки даты
   сообщения ГдеБЕНЗ вместо оплаты. Подтвердить данные API и карточек.

## Реализация после исследования

По последующему запросу пользователя реализован `providers/bank-http.js`:
дополнительный CA ограничен двумя банковскими хостами, TLS-проверка включена,
gzip сокращает загрузку общего каталога Альфы. Сбер сначала запрашивает JSON
напрямую; готовность резервного браузера проверяется через API метаданных.
Для Альфы убран преждевременный 12-секундный предел карты: 30 секунд на цикл
запроса с cookies, 35 секунд на клиенте. Остальные маркеры приходят потоком.

Локальный HTTP `/api/stations` после изменений вернул `available=true` для
Альфы, T-Bank и Сбера. Объединённые станции содержат указанные выше цены Альфы
и банковские даты оплат. Настройки системного доверия и секреты не менялись.
Все 194 теста прошли. `docker compose build` выполнен; сквозной HTTP-запрос
в отдельном контейнере `benz-ai:local` с Node.js 22.23.1 также подтвердил
доступность всех трёх банков, цены и оплаты обеих станций. Контейнер проверки
автоматически удалён, запущенные приложения не перезапускались.
Результат на BotHost требуется проверить после его пересборки.
